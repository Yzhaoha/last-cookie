# 最后一块饼干 Last Cookie v3「抢饼干」— 交接（2026-11-21，云端会话 → 本地会话）

## ★ 给本地会话：从这里接着做
用户要在自己电脑上开本地会话接手。云端会话做不了的两件事正好本地能做：登录 Cloudflare、用 Chrome 提交 CrazyGames。

**第一件：把联机服务器放上线**（代码已写好并在云端本机测通，见下面「联机」一节）
1. `git pull`（main 分支就是最新的），`cd server && npm install`。
2. `npx wrangler login`：会打开浏览器，让用户自己点授权（用户已有 Cloudflare 账号，是以前买域名时开的；不替他输密码）。本地这样登录就行，**不需要**云端会话想要的那个 API 令牌。
3. `npx wrangler deploy`。第一次可能要求先注册一个 workers.dev 子域名，按提示让用户自己选名字。成功后会打印地址，形如 `https://last-cookie.<子域名>.workers.dev`。
4. 把这个地址写进 `server/url.txt`（一行），回仓库根目录 `python3 tools/build.py`，提交并推到 main。
5. 给用户新的试玩链接 `https://yzhaoha.github.io/last-cookie/?v=提交号`，让他拉朋友（或自己开电脑 + 手机）同时点开始，5 秒内进来的人会进同一局。
6. 重点看：**真实网络下自己移动有没有延迟感、别人会不会瞬移、抢饼干的判定对不对**。这些云端没法测，是最大的未知数。出问题先看 client.js「联机」一节和 `SIM.applySnap`（sim.js 末尾）。

**第二件：提交 CrazyGames**（用户确认封面、视频、各语言之后）
材料都在仓库里：`release/last-cookie-crazygames.zip`、`submission/` 里的 3 张封面、2 段视频、`表单文字.md`。规矩见下面「用户规矩」。注意：`server/url.txt` 有了以后重新 build，zip 里的游戏也会带联机；带联机提交的话 CrazyGames 有额外要求（把房间信息报给它的 SDK，见 docs.crazygames.com/requirements/multiplayer），还没做。想先不带联机提交，就在 build 前把 `server/url.txt` 挪开。

**云端会话最后停在哪**：让用户建 Cloudflare API 令牌、弹安全表单时，用户决定改用本地会话，表单没填，**没有任何令牌或密码留在仓库或聊天里**。

## 游戏现状（11-17 大改：v3「抢饼干」）
用户试玩 v2（站饼干别掉下去）后说：场地太小跑不开、没意思，要大改。选了「抢饼干」方向，v2 的碎饼干/牛奶/小鱼全部删掉（要看去 git 历史 a3ca74c）。

现在的玩法：大桌面（52×36 米，格子桌布，上面有杯子、碗、书等障碍），你 + 7 个机器人，全场只有一块饼干。走过去捡；抱着它就在吃，**累计抱满 24 秒就赢**（保险上限 180 秒，到点谁吃得多谁赢）。空格/K 冲撞：撞到抱饼干的人就直接抢过来（刚抢到有 1.5 秒保护，冲撞马上又能用，好甩开人）。被撞飞出桌边会掉下去，2 秒后回来、豆子减半、饼干留在桌边；自己走/冲不会出桌。桌上的巧克力豆吃了变大（撞人更狠、更抗撞、略慢）。

用户说「豆太少、玩法还行但单调」→ 加了：豆 28→64 颗；**升级三招**（1 级冲得更远，2 级冲撞落地震开一圈人，3 级抱饼干时护盾挡一次、12 秒恢复）；**道具**（辣椒加速 4 秒、冰块冻住 8 米内的人 1.6 秒、泡泡挡一次撞，桌上最多 4 个）；**果酱**踩上去变慢；赢的门槛改成累计 25 秒。

用户以为「到时间才算赢，大家最后才抢」→ 其实一直是累计制，是界面的倒计时误导。已改：去掉倒计时，左上角改成显示领先者（👑 名字 百分比）；先到 100% 立刻赢；180 秒只是保险，最后 20 秒才显示倒计时。

用户问「只有撞一个招吗」→ 加了第二个键**跳**（J / Shift，手机蓝色按钮）：空中 0.55 秒撞不到你、能跳过果酱，冷却 2.2 秒；**震地改成 2 级起跳起落地时触发**（不再是冲撞结束时）。机器人抱饼干时会跳着躲冲撞。

## 当前数据（sim-test 100 局）
一局约 90 秒（约 1/4 打满 120 秒），饼干平均 5 秒换一次手，每局约 3 人次掉桌；“真人”第一名约 50%（偏容易，等用户反馈再调）。用户说 v3「有点意思，但控制跟不上趟」→ 已改：起步几乎不滑、真人冲撞自动对准抱饼干的人（`AIM_R`、`AIM_ANG`）、冲撞冷却 1.2 秒且可提前按、被撞晕 0.35 秒、真人快 5%、镜头跟得更紧、手机降分辨率。用户仍说「按了方向人物跟不上」→ 怀疑是画面帧数低/高刷屏抖动：逻辑改成每帧按实际时间走（不再固定 60 步）、卡了自动降画质（`autoQuality`，暂停菜单底部显示帧数和画质档）。还没确认用户是手机还是电脑。

## 11-20 用户确认：电脑不卡了、手机不放大了、人物跟得上了 ✅。新反馈：「追不上抱着饼干跑的人」
已改：抱饼干的机器人更慢（`CARRY_SLOW` 0.88）、别人抱着时真人追得更快（`ME_CHASE` 1.07）、机器人被真人追时很少用冲刺甩开。sim-test 里“真人”第一名升到约 65%（代打的是机器人，真人没那么准，所以先偏容易；用户说太简单再把 `ME_CHASE` 调回去）。

用户又说「还是追不上」→ 判断真正原因是“冲撞撞不中 + 目标老在保护期”，不是跑速。已改：真人冲撞会追着目标拐弯（`p.home`）、冲得更远（`ME_DASH`）、判定放宽（`ME_PAD`）、自动对准范围 5.4 米近乎全方向；别人刚抢到的保护期对真人只有 0.5 秒（`ME_GUARD`）；机器人基本不再跳着躲真人。sim-test “真人”第一名约 75%（代打偏强），等用户说是否太简单。

用户确认「能追上也能抢过来」✅。新反馈：「大家抢来抢去一直换人」→ 已改：同时追的机器人 3→2（`CHASERS`）、保护期 1.5→2.5 秒（对真人仍只有 0.6 秒）、机器人出手更慢（`BOT_RATE`、`BOT_REACT`）、获胜门槛回到 30 秒。sim-test：每次抱住 3 秒→近 6 秒，每局换手 25 次→15 次，一局约 91 秒；“真人”第一名约 78%（偏容易，等用户说）。

## ⚠️ 11-20 用户定的原则：规则必须对所有人一样
用户原话：「到时游戏上线全都是真人，也能换手不那么频繁，但也不是抢不过来」。所以**不许再给“真人”开小灶**（之前的 ME_SPEED / ME_CHASE / ME_GUARD / ME_GENTLE 等全部删了），换手频率要靠人人相同的规则来控制：
- 冲撞自动对准 + 途中跟着目标拐弯（有转弯上限 `HOME_TURN`，急转/跳能躲）、追人时冲得更远（`CHASE_DASH`）、判定放宽（`PAD`）——人人都有，保证“抢得过来”。
- 刚抢到：保护 2.5 秒（`GUARD_T`）+ 加速 35% 持续 2 秒（`GRAB_BOOST`）冲出人堆；刚被抢：2 秒不能冲撞（`ROBBED_CD`），不能立刻抢回——保证“不会秒换手”。
- 抱着饼干慢 7%（`CARRY_SLOW`），所以迟早被追上。
- 机器人只有“水平”参数（`CHASERS` 同时几个人追、`BOT_RATE`、`BOT_REACT`），不改规则。
验证方法：`CHASERS=7 node tools/sim-test.js 100` 模拟人人都在追。现在数据：默认（4 人追）一局 88 秒、每次抱住 5.3 秒、每局换手 16 次；7 人全追时抱住 6.5 秒。0 号“真人”第一名 18%（和机器人同等水平时本该 12.5%）。获胜门槛 24 秒（8 人平分时间，门槛高了一局太长）。

## 联机（11-21 写好并在本机测通，**还没部署**）
用户决定用 Cloudflare 免费档（用户自己的账号；不替他注册、不碰密码，要授权时用安全表单）。免费上限：每天 10 万请求（收到的消息 20 条算 1 次）、1.3 万 GB·秒（≈ 所有房间合计每天开 29 小时）。估算：500 人每人 3 局够，每人 5 局会超；超了当天连不上，游戏自动退回机器人局。
- **怎么工作**：服务器说了算。`server/room.js` 是房间规矩（等人 5 秒 → 开局 → 每秒 30 次推进、15 次广播局面，空位机器人补，掉线机器人接手），跑的就是 `src/sim.js`。`server/worker.src.js` 是 Cloudflare 那层（Room / Matchmaker 两个 Durable Object）。`python3 tools/build.py` 把三者拼成 `server/worker.js`。
- **游戏端**（client.js「联机」一节）：点开始 → `findMatch` 连 `<地址>/join`；9 秒内没开成 / 连不上 / 满了 → 照旧打机器人局。联机时本机 `S.net=true`：自己移动本机先走（不等服务器，没有延迟感），谁抢到 / 掉下去 / 吃豆 / 输赢只听服务器（`SIM.applySnap`、`NET_EVENTS`）。3 秒没消息或断线 → `netLost()`，其余人交给本机机器人接着打完。
- **地址**：打包时从 `server/url.txt` 读（没有这个文件 = 纯单机，现在线上就是纯单机）；测试可在网址加 `?net=地址`。
- **本机测试**：`cd server && npm install && npx wrangler dev --port 8787`，游戏开 `?debug&net=http://127.0.0.1:8787`。已验证：3 个连接配进同一房间；浏览器 + 程序玩家互相看得到对方移动、位置和服务器一致；断线后自动变机器人局。注意无头浏览器同时开两个页面时后台页会被压得很慢，别用它测“两个浏览器进同一房间”。
- **还没做**：部署（等用户注册好账号：`cd server && npx wrangler deploy`，把得到的地址写进 `server/url.txt` 再 build）；真实网络延迟下的手感没测过；局面包每个约 1.5KB×每秒 15 个，可以再压；CrazyGames 对联机游戏的额外要求（把房间信息报给它的接口）没做；玩家昵称现在是自动起的 `Cookie123`。
